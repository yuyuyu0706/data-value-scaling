# 分析

`analytics/` は、合意済みの定義と承認済みの入力を使う、再現可能な分析実行物とレビュー対象の分析結果を管理する領域です。「入力と定義を使って、どのように分析するか」を、第三者が確認・再実行できる状態にします。

物理配置と責務境界の正本は [Repository 構成ガイド](../docs/00_project/repository-structure.md)、正本・更新・参照方法の共通ルールは [文書管理ルール](../docs/00_project/document-governance.md) を参照してください。

## 配置するもの

- 分析クエリ
- 再現可能な Notebook と分析コード
- 実行条件と再現手順
- レビュー対象として保持する再現可能な分析結果

次のものは `analytics/` には配置しません。

- 指標、用語、データモデル、算定式などの定義の正本
- 原データや入力データの正本
- アプリケーション本体
- 再現手順のない手作業の結果や、個人用の試行ファイル
- 機密情報、個人情報、資格情報を含む入力や出力

分析物は `definitions/` の合意済み定義と `data/` の承認済み入力を相対リンクや明示した取得手順で参照します。定義や原データを分析物へ複製せず、分析方法と結果の責務を分離してください。

## 新しい分析を追加する前に

関連 Issue で次を定義し、レビュー可能な状態にしてから追加します。

1. 分析の目的、利用者、判断への利用方法
2. 参照する定義と入力、および入力の取得条件
3. 出力の形式、配置、期待する評価・確認方法
4. ランタイム、ツール、依存関係、バージョンなどの実行環境
5. 実行コマンド、処理順序、乱数や時点の固定を含む再現手順
6. 分析物を保守する責任者と、更新・廃止の契機

入力と出力については、`data/` と同じく機密性、個人情報、資格情報、ライセンス、容量、保持条件を確認します。実際の成果物から共通の分類軸が明確になるまでは、将来用途だけのサブディレクトリや空ファイルを作成しません。
