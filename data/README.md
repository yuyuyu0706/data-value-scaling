# データ

`data/` は、再現可能な分析に必要で、Repository での保持が承認された小規模データ、サンプル、スキーマ、取得・生成手順を管理する領域です。「何を入力として利用するか」を明確にし、安全性、由来、再現性を確認できる状態にします。

物理配置と責務境界の正本は [Repository 構成ガイド](../docs/00_project/repository-structure.md)、正本・更新・参照方法の共通ルールは [文書管理ルール](../docs/00_project/document-governance.md) を参照してください。

## 配置できるもの

- Repository での保持が承認された小規模な入力データやサンプルデータ
- 入力データの構造を表すスキーマ
- 外部データの取得手順や、入力データを再生成する手順
- データの由来、利用条件、更新条件を確認するための付随情報

`data/` という名称だけを根拠にデータを格納してはいけません。次の情報は配置禁止です。

- 機密情報
- 個人情報
- API キー、パスワード、トークンなどの資格情報
- 利用条件や再配布可否を確認できないライセンス不明データ
- Git 履歴で管理することが不適切な大容量データ
- 出所や生成条件を確認できない無管理の生成物

一度 Git 履歴へ追加した情報は通常の削除だけでは履歴から消えません。機密情報、個人情報、資格情報を誤って追加した場合は、追加のコミットを続けず、漏えい対応と履歴からの除去を直ちに関係者へ相談してください。

## データを追加する前に

関連 Issue と Pull Request で、少なくとも次を確認します。

1. **機密性:** 機密情報、個人情報、資格情報を含まず、公開範囲が適切であること
2. **ライセンス:** 利用、複製、再配布、改変の条件が Repository での保持を許可していること
3. **容量:** 現在の容量と増加見込みが Git 履歴での管理に適していること
4. **保持期間:** 保持する目的、期間、更新・廃止条件が明確であること
5. **Git 管理の妥当性:** 差分レビュー、履歴保持、取得頻度を踏まえ、外部ストレージではなく Git で管理する理由があること

原データの正本が外部にある場合、データ本体を正本として複製するのではなく、提供元・参照先・取得日時などの**由来**と、認証情報を含めない取得または生成方法を記録します。入力の意味は `definitions/` の合意済み定義を参照し、分析コードや分析結果は `analytics/` に配置します。

実際の成果物から共通の分類軸が明確になるまでは、将来用途だけのサブディレクトリや空ファイルを作成しません。
