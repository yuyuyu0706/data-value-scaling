# 管理文書

`docs/` は、プロジェクト管理、方針、設計、運用など、人が読んで利用する説明文書を管理する領域です。物理配置と責務境界の正本は [Repository 構成ガイド](00_project/repository-structure.md)、正本・更新・参照方法の共通ルールは [文書管理ルール](00_project/document-governance.md) を参照してください。

## 配置するもの

- プロジェクトの目的、運営、文書管理に関する文書
- 合意した方針、設計、運用手順を説明する文書
- 人が参照することを主目的とし、既存の正本と責務が重複しない文書

次のものは `docs/` には配置しません。

- 複数の成果物へ継続的に影響する設計・運用判断の記録
- 機械処理を主目的とする指標・用語・データモデルなどの定義
- 実データ、分析クエリ、Notebook、分析コードや分析結果
- 一時的な検討メモ、個人用の作業メモ、生成物

各領域の詳しい配置基準は [Repository 構成ガイド](00_project/repository-structure.md) に従います。

## 現在の構成

```text
docs/
├── README.md
└── 00_project/
    ├── charter.md
    ├── document-governance.md
    ├── github-project-readme.md
    └── repository-structure.md
```

`00_project/` は、プロジェクト全体に関わる既存の管理文書を維持する領域です。現在は、プロジェクト憲章、文書管理ルール、GitHub Project の案内原稿、Repository 構成ガイドを管理しています。既存のファイルは移動・改名せず、新しい番号付き分類も、複数文書を継続的にまとめる必要が明確になるまでは追加しません。

## 新しい文書を追加する前に

1. 関連 Issue で目的、利用者、扱う情報、更新責任、更新契機を定義します。
2. 既存の正本へ追記すべき情報ではないか、既存文書の要約とリンクで解決できないかを確認します。
3. [Repository 構成ガイド](00_project/repository-structure.md) で配置先、責務境界、命名、追加条件を確認します。
4. [文書管理ルール](00_project/document-governance.md) で正本、参照方向、更新・レビュー方法を確認します。
5. 複数の性質を持つ場合は主な責務を一つ選び、他領域に内容を複製せず相対リンクで参照します。

新しいディレクトリは将来利用のために先行作成せず、必要な成果物と案内文書を追加する Issue で作成します。
