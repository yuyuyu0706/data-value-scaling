# 指標・共通定義

`definitions/` は、指標、用語、データモデル、算定式など、複数の文書や分析で再利用する**合意済み定義の正本**を管理する領域です。「何を、どのように定義するか」を一元管理し、説明文書や分析ごとの定義の複製と表記揺れを防ぎます。

物理配置と責務境界の正本は [Repository 構成ガイド](../docs/00_project/repository-structure.md)、正本・更新・参照方法の共通ルールは [文書管理ルール](../docs/00_project/document-governance.md) を参照してください。

## 配置するもの

- 合意済みの KPI・指標と、その意味や適用範囲
- プロジェクトで共通利用する用語
- データモデル、項目、値の意味に関する定義
- 算定式、単位、粒度、集計条件などの再利用する計算定義

次のものは `definitions/` には配置しません。

- プロジェクト方針や設計を説明する一般文書
- 原データ、サンプルデータ、データの取得・生成物
- 分析クエリ、Notebook、分析コード、分析結果
- 合意前の案、一時的な検討メモ、個人用の定義

データ自体は `data/`、定義と入力を使う分析実行物・結果は `analytics/` が担当します。他領域では定義の内容を複製せず、この領域の正本を相対リンクで参照します。

## 新しい定義を追加する前に

関連 Issue で次を合意し、レビュー可能な状態にしてから追加します。

1. 定義する対象、利用者、適用範囲
2. 人と利用ツールが解釈できる記述形式・ファイル形式
3. 正しさ、一貫性、後方互換性を確認する検証方法
4. 内容の所有者とレビュー責任
5. 業務ルール、入力仕様、利用目的など、定義を更新する契機

既存の正本と重複しないことを確認し、複数の性質を持つ成果物は主な責務を一つ選んで配置します。実際の成果物から共通の分類軸が明確になるまでは、将来用途だけのサブディレクトリや空ファイルを作成しません。
