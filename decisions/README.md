# 意思決定記録

`decisions/` は、複数の成果物へ継続的に影響する設計・運用判断を Decision Record として管理する領域です。判断、検討した選択肢、理由、影響を追跡できる状態にし、後続の作業で同じ論点を繰り返さないことを目的とします。

物理配置と責務境界の正本は [Repository 構成ガイド](../docs/00_project/repository-structure.md)、正本・更新・参照方法の共通ルールは [文書管理ルール](../docs/00_project/document-governance.md) を参照してください。

## 記録対象

- 複数の文書、定義、データ、分析、または運用へ継続的に影響する判断
- 将来の設計・運用で参照する必要がある、採用案と不採用案を含む判断
- 前提や制約が変わった際に、見直しの根拠が必要になる判断

次のものは Decision Record の対象にしません。

- 一時的な検討メモや個人用の作業メモ
- 作業状況、タスク一覧、Issue の進捗
- 個別の Pull Request だけに関する変更理由やレビュー履歴
- プロジェクト方針や設計を利用者へ説明する一般文書

これらは、それぞれ関連 Issue、Pull Request、または `docs/` 内の適切な正本で管理します。

## 現在の運用状態と暫定ルール

Decision Record の正式な仕組みは未整備です。テンプレート、採番方式、状態管理、ファイル名規則、一覧または Index の要否は未確定であり、この README では固定しません。個別の Decision Record も、正式な運用を決定するまでは追加しません。

正式整備前に永続的で複数成果物へ影響する判断を行う場合は、関連 Issue の「重要な設計判断・論点」に次を記録します。

- 合意した判断
- その判断に至った理由
- 影響を受ける成果物や後続 Issue

この暫定記録が判断の参照先です。既存 Issue の記録を将来の Decision Record へ移行する方法も、正式運用を決める後続 Issue で扱います。

## Decision Record を追加する条件

個別記録を追加する前に、後続 Issue で次の事項を合意し、レビューします。

1. 記録の目的、利用者、対象となる判断と対象外の情報
2. 必須項目を含むテンプレート
3. 採番方式とファイル名規則
4. 提案、採用、廃止、置換などの状態管理方法
5. 一覧または Index の要否と更新方法
6. 作成・レビュー・更新の責任と契機
7. Issue の暫定記録を移行または参照する方法

合意後は、同じ判断を一般文書へ複製せず、必要最小限の要約から Decision Record を相対リンクで参照します。
